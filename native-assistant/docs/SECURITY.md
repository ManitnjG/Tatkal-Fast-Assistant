# Security design

## Boundaries
IRCTC and the browser own credentials, sessions, CAPTCHA, OTP, payments and transaction confirmation. The assistant is not an IRCTC agent and does not claim affiliation. URLs are fixed HTTPS official origins; external browsing uses the system browser/Custom Tabs with normal certificate validation. There is no app network client and no INTERNET permission in the app manifest (dependencies may contribute permissions; inspect the merged manifest).

## At-rest protection
Passenger and journey profiles, mobile numbers, PNRs and snapshots are serialized inside one AES/GCM authenticated encrypted payload in Room. The key is generated by Android Keystore and is not exported; hardware backing depends on device support. Each encryption uses a new random 12-byte IV and a version/AAD boundary. Room journals also see ciphertext. The database row has only a constant ID and update timestamp outside ciphertext. Non-sensitive language/theme/app-lock preferences use DataStore.

The key is not authentication-bound. Device authentication gates app UI (enabled by default); this is not protection against a rooted/compromised device or arbitrary code execution in the app process. App locking can be disabled only inside the authenticated UI. Android backups and device transfer are excluded. Loss of the Keystore key is not recoverable; decryption failure is surfaced and never resets data automatically. Screenshot protection uses FLAG_SECURE. RAM plaintext exists while in use and Kotlin strings cannot be reliably wiped.

## Transaction safety
A mutex serializes state writes. New attempts require no unresolved attempt in any journey. The handoff lock persists before the external intent launches. After process recreation, handed-off unresolved attempts become UNKNOWN. Pending/unknown cannot automatically advance or reset. Session expiry during payment stays UNKNOWN. Failure or success resolution requires explicit user confirmation of official history and payment state; success additionally requires a ten-digit PNR. The app does not infer a refund, failure, seat or PNR from a timeout. A manual acknowledgement is not authoritative server verification. Users can still create duplicate bookings outside this app.

## Clipboard and sharing
Copy requires a deliberate tap. Android 13+ clipboard data is marked sensitive. The app attempts to clear its matching value after 60 seconds; Android background execution or process termination may prevent this. IMEs and other apps may retain a copy. No secrets are copied. PNR and allocations are sensitive travel information. Share uses the Android chooser and omits passenger names, phone and payment details.

## Data handling
No logging of user data, analytics, ad SDK, cloud sync, remote CAPTCHA service, password store, OTP read permission or automated retry loop. Notifications contain no journey or passenger data. Release signing uses Actions secrets; signing material is removed in an always-run cleanup step. Do not upload debug keystores or replace a release identity casually.

## Before public production release
Review dependency vulnerabilities, distribution requirements and IRCTC terms; run the documented device test matrix and independent security review. The source is functional preparation software, not a claim of independently audited production readiness. Authorized future integrations must maintain these boundaries and use server-authoritative idempotency/status checks before expanding payment automation.


## v0.2.0 Autofill boundary
An OS AutofillService protected by BIND_AUTOFILL_SERVICE is exported solely for framework binding. The review activity is not exported. Chrome's package name and its signing certificate/verified signing lineage are checked before considering a request. The accepted Google certificate is published in Google's HTTPS Digital Asset Links file. Exact IRCTC host and HTTPS scheme are inherited only through the relevant view subtree; a child origin overrides its parent. No arbitrary suffix matching or trust-on-first-use is allowed. Android 8 lacks the required web-scheme API, so web autofill is disabled there.

Only visible text fields in the focused partition with explicit allowlisted semantic descriptors qualify. Password input variations and security/payment keywords veto all other matches. The service never reads ViewNode.text or autofillValue, never records a form, and never offers SaveInfo. Depth/node limits bound tree traversal. Suggestions carry no passenger data and require device authentication plus value review. A random, single-use token binds the target AutofillIds for 120 seconds. The immutable PendingIntent carries no personal data. The target is discarded after process death; a fresh request is required. Before returning data, the browser identity, expiry and current attempt state are checked again. The OS owns actual field application; there is no click or submit automation.

This is a conservative integration, not a claim that every live IRCTC field exposes usable metadata. Browser signature rotation outside a recognized lineage fails closed until a reviewed update. Test on the intended browser/device before time-sensitive use.

## v0.3 portable backups and grouping

Backups have a fixed TFA/version header, random 16-byte salt and 12-byte nonce. The header, salt and nonce are GCM additional authenticated data. PBKDF2 iterations are fixed rather than attacker-controlled. Input is capped at 8 MiB before decryption; schema, ID uniqueness and collection/field bounds are checked before merging. Import is a single VaultStore transaction with existing Keystore encryption. Import never replaces the vault wholesale or silently resolves a pending attempt. Backup operations require device authentication even if the main app lock is disabled; the backup screen excludes OS autofill and screenshots. Secrets are not saved in instance state, and mutable key/plaintext buffers are cleared where practical. JVM strings cannot be guaranteed erased immediately. A deliberately chosen document provider receives only encrypted bytes.

Grouped autofill is limited to direct siblings of the focused field, exact matching origin, and the same passenger-versus-journey partition. Each semantic field must be unique among candidates in that group; ambiguous focus falls back to the focused field alone. Hidden ancestors, truncated trees and multiple focused candidates fail closed. All values are displayed before confirmation. The OS may cache a returned dataset as part of the current autofill session; this app does not promise that a browser clears already-filled values or that the framework re-authenticates every later selection in that session.

The duplicate-attempt guard applies to new attempts started inside this assistant. It cannot prevent independent bookings made directly in IRCTC or another app. Opening the official site to verify history does not itself prove or resolve a transaction.
